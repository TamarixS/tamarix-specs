## Рекомендуемый формат будущего ADR

Файл: `NNNN-краткое-имя.md`; нумерацию и шаблон команда может уточнить.

- Заголовок, дата, статус `proposed / accepted / rejected / superseded`.
- Проблема, исходные факты, ограничения и затронутые capabilities/репозитории.
- Рассмотренные альтернативы, выбранное решение и причина выбора.
- Последствия: API, данные, security, эксплуатация, совместимость и стоимость.
- План перехода, проверка результата, восстановление/откат и нерешённые вопросы.
- Ссылка на change, источник явного принятия, reviewer/approver после их определения.
- При замене решения — ссылки между старым и новым ADR и дата изменения статуса.

Только `accepted` с подтверждённым принятием и применимой областью действия
служит утверждённым архитектурным решением. Обнаруженный код отдельно подтверждает
реализацию, но не превращает предложенный ADR в принятый. Историю не переписывать;
при изменении решения оформить замену и обновить затронутый context.
