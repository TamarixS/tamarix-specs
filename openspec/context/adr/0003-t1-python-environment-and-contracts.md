## Проблема и границы

Для реализации согласованного логического ядра нужны воспроизводимые проекты,
автоматизированные проверки критериев specs и размещение контрактов поставщиков
фактов. До задач 2.2–2.3 build backend, testing framework и точные локальные
интерфейсы оставались TBD.

Решение применяется к пяти репозиториям: `container-adm-api`,
`entity-subject-adm-api`, `entity-object-adm-api`, `policy-adm-api`,
`policy-decision-api`. `db-control` и `access-assignment-api` этим выбором
не получают кодовых задач T-1. Общий утверждённый стек сохраняется для будущих
API/данных; их зависимости не добавляются в ядро без потребности.

Официальные страницы повторно проверены 2026-10-09. На момент принятия совместимость
подтверждена опубликованными ограничениями, а не выполнением кода на этом наборе.

Выбраны устанавливаемые pure-Python пакеты с `src/`, build backend `uv_build`,
`dependencies = []` и dev-группа pytest. В `pyproject.toml` задаются проект,
pins и `prerelease = "disallow"`; прямые и транзитивные dev-зависимости
фиксируются в `uv.lock`. Номер final нельзя заменять rc или более старой
версией без отдельного решения. Пример полного манифеста и команды находятся
в принятом python-environment.md.

## Принятые локальные интерфейсы

Каждый репозиторий владеет своими модулями и типами:

- `src/<package>/facts.py` — значения и различимые результаты.
- `src/<package>/ports.py` — Protocol поставщиков и потребителей фактов.
- `src/<package>/core.py` — предметные операции соответствующего сервиса.

Имена пакетов: `container_adm_api`, `entity_subject_adm_api`,
`entity_object_adm_api`, `policy_adm_api`, `policy_decision_api`.
Общий runtime-пакет не создаётся; внутренние классы соседних сервисов не
импортируются. Адаптеры преобразуют значения между локальными контрактами.

Контракты разделяют `CompletePath / UnknownPath`,
`CompleteModelSet / UnknownModelSet`, подтверждённого вызывающего/отказ запроса
и `Allow / Deny / Neutral / Undefined` отдельной известной модели.
Полнота пути включает оба конца; полнота списка подтверждает набор каждого
запрошенного контейнера, включая явный пустой набор. Отсутствие части списка
или контейнера означает unknown; недостающий результат известной модели нельзя
выдать за полный набор результатов.

Неуспешный допуск, некорректные обязательные входы/адресация и ошибки получения
обязательных entity-фактов отделены от Undefined известной модели.
Неизвестный полный путь/состав моделей даёт Deny; при установленном составе
Undefined известной модели нейтрален. Предметные ключи, DN, action и ContainerRef
остаются логическими значениями; wire-форматы и сравнение не выбираются.
Точные порты, входы, результаты и примеры приведены в logical-contracts.md.

## Альтернативы и последствия

Для testing рассмотрен стандартный unittest: он не добавляет dependency,
но pytest выбран для именованной параметризации сценариев/таблиц и связей с
критериями specs. Для сборки рассмотрен Hatchling; сложных build scripts
текущее ядро не требует, выбран минимальный uv_build.

Общий пакет типов потребовал бы владельца, выпуска, версии и совместимости
между репозиториями. Локальные контракты сохраняют независимость, но требуют
явных адаптеров и сквозных проверок соответствия. Разделение complete/unknown
добавляет типы и проверки, зато не скрывает неполный источник за пустым списком.

Python 3.15.0 опубликован 2026-10-09. На момент принятия его доступность на выбранной
локальной платформе и совместимость установленного набора ещё предстоит
проверить. Read-only срез при подготовке 2.2: Homebrew uv 0.12.23,
system Python 3.9.6 и uv-managed Python 3.13.16; offline-каталог uv тогда
содержал только 3.15.0rc3 для ветки 3.15. Наличие стабильного релиза на
python.org не доказывает доступность final в каталоге managed Python.

## Переход и проверка

Задачи 2.2–2.3 фиксируют принятие. Задача 3.1 сначала проверяет доступность
именно final Python 3.15.0 и uv 0.12.24 и подготавливает первый проект.
Остальные проекты используют тот же согласованный набор. При невозможности
получить final зависимые задачи остаются открытыми; prerelease или молчаливый
downgrade не используются.

В каждом проекте предусмотрены:

```sh
uv lock
uv lock --check
uv sync --frozen
uv run --frozen --no-sync python --version
uv run --frozen --no-sync python -m pytest -q
uv build --no-sources
```

При нуле тестов запуск pytest не подтверждает завершение. Реальные тесты
создаются по группам задач и проверяют требования/сценарии четырёх delta specs.
Команды, версии, revision и результаты записываются в центральном
[tasks.md](../../changes/archive/2026-10-13-t-1-container-definition/tasks.md).

На момент фиксации ADR подтверждены принятие и официальные метаданные:
lock/install/build и автоматизированные тесты этого набора ещё не выполнены.
Документация и тестовые факты не доказывают runtime-интеграцию.

Изменение принятой среды или контрактов требует согласования и новой записи
решения с сохранением истории. Документальное изменение обратимо через Git;
откат кода/окружения проектируется по реальным артефактам и проверкам, без
предположений о production-данных.
