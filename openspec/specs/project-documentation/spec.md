# project-documentation Specification

## Purpose

Определяет состав актуального руководства Tamarix и обязательное сопровождение
документации центрального store при архивировании новых OpenSpec changes.

## Requirements

### Requirement: Полное руководство проекта

Центральный store MUST содержать восемь связанных русскоязычных страниц
`docs/{README,architecture,domains,services,api,database,operations,development}.md`.
Руководство SHALL объяснять архитектуру/домены/сервисы/API/БД и эксплуатацию,
использовать Mermaid и отличать реализацию от TBD.

#### Scenario: Полный комплект документов

- **WHEN** описаны продукт, слои/ответственность/взаимодействия, API, таблицы/связи/примеры/constraints/indexes/locks/риски, все страницы существуют, локальные ссылки разрешаются и Mermaid blocks непустые
- **THEN** структурная проверка MUST завершиться успешно; критерий приёмки: exit code 0 и отсутствие ошибок

#### Scenario: Неполное руководство

- **WHEN** отсутствует обязательная страница, есть битая внутренняя ссылка или пустая Mermaid-схема
- **THEN** проверка MUST завершиться ошибкой с путём и причиной; критерий приёмки: ненулевой exit code

### Requirement: Обновление документации до archive

Для каждого нового change, включая tooling/docs-only и bulk archive, агент MUST
сверить все восемь разделов, обновить затронутые страницы и сохранить
`docs-review.json` с результатом каждого раздела, русским обоснованием,
списком фактически изменённых страниц, baseline commit и SHA-256 change/docs.
Полный текст страниц SHALL сохраняться в проверяемом content snapshot.
Обёртка archive MUST проверить evidence до изменения specs или переноса change.

#### Scenario: Актуальное обновление

- **WHEN** документация обновлена относительно сохранённого baseline, все разделы reviewed/updated и SHA-256 соответствуют входам
- **THEN** docs gate SHALL допустить последующие существующие archive-проверки; критерий приёмки: docs validation успешна без запуска тестов или переноса change

#### Scenario: Отсутствующий или устаревший обзор

- **WHEN** evidence отсутствует, раздел pending, нет реального обновления либо после review изменён change или документ
- **THEN** archive MUST остановиться до мутаций; критерий приёмки: change остаётся активным, specs и тестовый registry не изменены

### Requirement: Проверка нового архива в CI

CI MUST проверять documentation evidence новых архивов относительно Git base
и отклонять обход обёртки. Сохранённые хэши старых архивов SHALL оставаться
историческими снимками и не требовать совпадения с будущими docs.
CI/обёртка SHALL сохранять существующие требования regression evidence и
не SHALL запускать предметные тесты неявно.

#### Scenario: Новый архив без documentation evidence

- **WHEN** в diff появляется новый archive без корректного docs-review.json
- **THEN** CI SHALL завершиться ошибкой; критерий приёмки: ненулевой exit code с именем архива

#### Scenario: Исторический архив после обновления docs

- **WHEN** docs изменились в следующем change, а прежний архив не менялся
- **THEN** его старый documentation snapshot SHALL не блокировать CI; критерий приёмки: historical hash не сравнивается с current docs

#### Scenario: Последовательный batch с разными снимками

- **WHEN** относительно одного Git base добавлены два архива с разными полными docs snapshots
- **THEN** CI SHALL проверить каждый snapshot и потребовать совпадение текущих docs хотя бы с одним новым snapshot; критерий приёмки: корректный batch проходит, одиночный stale snapshot отклоняется

#### Scenario: Подмена принятого исторического evidence

- **WHEN** review/snapshot прежнего архива и их hash-поля самосогласованно изменены относительно Git base
- **THEN** CI SHALL отклонить изменение; критерий приёмки: ненулевой exit code, прежние snapshots считаются неизменяемыми
