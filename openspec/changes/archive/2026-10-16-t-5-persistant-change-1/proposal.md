# Proposal

## Why

Тип, кратность и правила сравнения атрибутов сейчас копируются из definitions
в четыре семейства instances. Для общих именованных форм и будущих ограничений
значений нужен единый неизменяемый контракт, который несколько определений
смогут явно переиспользовать без расширения всех таблиц экземпляров.

## What Changes

- Ввести общий каталог `attributes.shapes`: `id`, `key`, тип, кратность,
  профиль и закреплённая версия сравнения. Зарегистрированный shape неизменяем
  целиком; другая семантика получает отдельные `id` и `key`.
- Для `shape.key` принять подтверждённый пользователем контракт: обязательный
  ASCII `[A-Za-z0-9_-]`, 1–512 символов, глобальная уникальность без учёта
  регистра ASCII, неизменяемость. Каталог возвращает key и точный shape ID
  для будущего UI; разработка UI не входит в изменение.
- Привязать каждое definition к одному shape, сохранив собственные id/key
  и явную применимость. Разрешить перепривязку только без любых instances,
  включая пустые sets и атрибуты логически удалённых субъектов.
- В instances оставить `shape_id` и структурные копии типа/кратности,
  защитив соответствие составными FK. Удалить физические копии профиля/версии
  сравнения; сохранить локальные CHECK, single-index, deferred cardinality,
  equality guard, DN и CAS.
- Добавить защищённые SQL-операции регистрации/чтения shapes и назначения
  формы. Сохранить прежние сигнатуры catalog routines и схемы fact views
  совместимыми через wrappers и явные проекции JOIN.
- Перенести существующие данные новой Alembic revision в `db-control`,
  проверить переход заполненной БД, конкурентные сценарии и совместимость
  потребителей; спланировать восстановление и ограничения downgrade.
- При применении выявлен разрыв между component-only критериями и archive
  coverage. После сообщения об этом пользователь 2026-10-16 попросил продолжить:
  gate дополнен проверкой неизменного component PASS bundle db-control с
  run-start provenance, без ослабления полного integration regression.
- Подготовить расширение validator через shape. Regex, length/range rules,
  generic JSON rules, наследование, floating latest и автоматическая
  дедупликация форм в scope не входят.

## Capabilities

### New Capabilities

Нет: формы являются частью существующей capability атрибутов.

### Modified Capabilities

- `attributes`: общий именованный каталог форм, неизменяемая семантика,
  назначение зарегистрированного shape, защита используемой привязки,
  структурная целостность и совместимый переход хранения.

## Impact

- `db-control`: единственный владелец новой миграции, DDL, guards, catalog
  routines, grants, views и component/migration tests.
- `TamarixTests`: новые integration cases с постоянными ID, обновление связей
  действующего регресса attributes/DN/fact views и отчёты согласованных прогонов.
- `tamarix-specs`: delta `attributes`, design/tasks, последующее сопровождение
  docs и evidence. Сохранённый `requirements.md` — источник scope; контракт key
  уточнён явным ответом пользователя 2026-10-16.
- Потребители совместимых контрактов: `container-adm-api`,
  `entity-subject-adm-api`, `entity-object-adm-api`, `policy-adm-api`,
  `policy-decision-api`. Их SQL/Python поведение проверяется регрессом;
  собственные миграции или новые бизнес HTTP endpoints не добавляются.
- Поведение `containers` и `authorization/access-check` сохраняется и
  проверяется существующим регрессом. `access-assignment-api` и `TamarixCD`
  не требуют изменений кода; новая среда и обновление зависимостей не выбираются.

Изменение физического хранения выполняется в обслуживаемом окне: до commit
сбой откатывает транзакцию; после commit прежние consumers продолжают работать
через совместимые контракты. Production recovery и test-only downgrade
различаются: старая схема не представляет новые key/ID и sharing каталога
shapes. Детали и проверки приведены в design и tasks; наличие плана не
подтверждает выполнение миграции или тестов.
