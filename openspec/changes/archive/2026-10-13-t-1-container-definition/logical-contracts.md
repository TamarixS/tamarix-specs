## Размещение и границы

В каждом из пяти проектов реализованы локальные модули:

- `src/<package>/facts.py`: значения и различимые результаты.
- `src/<package>/ports.py`: Protocol интерфейсов поставщиков/потребителей.
- `src/<package>/core.py`: предметные проверки и операции своего сервиса.

Пакеты: `container_adm_api`, `entity_subject_adm_api`,
`entity_object_adm_api`, `policy_adm_api`, `policy_decision_api`.
Каждый репозиторий владеет своими типами. Адаптеры преобразуют значения между
локальными контрактами; общий runtime-пакет и импорты внутренних классов
соседних сервисов не вводятся.

ContainerRef, ключи сущностей, DN и action — логические значения.
Формат/сравнение wire-ключей и DN, внутренние ID и сериализация не выбираются.
Предметное дерево использует однозначно разрешённые контейнеры, а проверенные
сертификатные факты поступают от отдельной доверенной границы; тестовый факт
не заменяет настоящий сертификатный адаптер.

## Входы и результаты

| Репозиторий | Логический контракт | Вход → результат |
| --- | --- | --- |
| container-adm-api | ContainerFactsPort.resolve, path_to; AdmissionPort.admit | Ключ → разрешённый ContainerRef или ошибка разрешения; R → CompletePath(root…R) / UnknownPath(reason); C, O, проверенный сертификатный факт → AdmittedCaller(C,O) / RequestRejected |
| entity-subject-adm-api | SubjectFactsPort.get; потребительские порты дерева/допуска; управление | Ключ → SubjectFacts(subject_ref, единственный holder); подтверждённый вызывающий и фактический держатель данных → проверка O ≼ C ≼ D до изменения |
| entity-object-adm-api | ObjectFactsPort.get; потребительские порты дерева/допуска; управление | Объект → ObjectFacts(object_ref, единственный holder); держатель объекта задаёт R; управление проверяется до изменения |
| policy-adm-api | ModelFactsPort.models_for; читающие порты дерева/сущностей; управление и ссылки | Контейнеры пути → CompleteModelSet / UnknownModelSet(reason); ссылки → проверка H(S) ≼ M и M ≼ H(Q), без изменения держателей сущностей |
| policy-decision-api | Локальные потребительские порты всех фактов; ModelEvaluatorPort.evaluate; операторы | Подтверждённый C/O, субъект, объект, действие → отдельный отказ некорректного входа либо EvaluatedDecision(Allow/Deny); известная модель → Allow/Deny/Neutral/Undefined |

CompletePath подтверждает весь путь и оба конца; обрезанный путь — UnknownPath.
Авторитетный `container-adm-api` проверяет действительные связи родителей
и порядок типов. Потребительский DTO проверяет форму подтверждённого пути;
доказательство его полноты относится к поставщику, а не к одному DTO.
CompleteModelSet подтверждает набор каждого запрошенного контейнера, включая
явный пустой набор. Пропущенный контейнер или часть списка — UnknownModelSet.
Оператор цепочки получает полный состав и результат каждой известной модели;
недостающий результат нельзя выдавать за полноту.

Модельные ссылки содержат ссылки на исходные сущности; policy-adm-api
получает их держателей через читающие порты. Изменение держателей entity-сервисов
этим интерфейсом не предоставляется. Управление с неустановленной областью
не допускается к изменению.

Отсутствующие обязательные входы, неуспешный сертификатный допуск и
недопустимая адресация — отдельные ошибки запроса, а не Neutral/Undefined модели.
Сбои получения обязательных entity-фактов также различимы с неопределённостью
отдельной известной модели; их wire-отображение остаётся вне текущего контракта.
Отказ получения полного пути или полного набора моделей даёт именно Deny.

## Примеры для проверки

| Факты | Результат |
| --- | --- |
| Полный путь, для каждого контейнера явно models=() | Полный пустой состав, Deny по умолчанию |
| Обрезанный путь либо неизвестен полный набор моделей узла; доступная модель разрешает | Unknown состава, Deny |
| Полный состав, субъект вне области модели | Neutral этой модели |
| Полный состав, известную модель невозможно вычислить, другая разрешает, запретов нет | Undefined модели, итог Allow |
| Полный состав, есть Deny и Undefined | Итог Deny |
| Сертификат подтверждён, DN зарегистрирован за O, отдельной роли нет | Владелец признан; управление затем ограничивается областью и инвариантами |

Такое размещение позволяет проверять реальные операции сервисов тестовыми
адаптерами. Альтернатива — общий пакет типов, который потребовал бы отдельного
выбора владельца, выпуска и совместимости; текущий вариант сохраняет независимость
репозиториев. Точные имена внутренних классов могут уточняться без изменения
логического поведения; фактические тестовые идентификаторы отражаются в tasks.

Wire API, PKI/trust, физическое хранение, согласованность конкурентных операций,
конкретные движки, ошибки отдельных правил и deployment этим документом
не выбираются. Эти границы не подтверждаются тестовыми поставщиками.
